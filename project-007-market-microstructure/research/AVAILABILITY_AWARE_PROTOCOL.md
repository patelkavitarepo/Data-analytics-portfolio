## Scientific motivation and question

D012's nominal two-percent high-score alerts produced ~84% incorrect directional warnings; D013 found substantial later score-tail drift. D014 was **not a directional model test**: the first prospective source runner failed closed due to `000025.SZ` missing valid depth on May 30 and June 2; a separately frozen postmortem found near-empty additional days, even when source timestamps existed. Those *already-observed* D014 dates are explanatory/hypothesis-generating and must not be recycled to optimize performance or silently excluded.

**Research question:** Can a decision system distinguish (1) an invalid/missing current source observation, (2) a valid observation but insufficient historical data quality for a robust rolling score cutoff, (3) valid data and no directional score above the threshold, and (4) an emitted up/down alert? Report coverage and missed-event visibility independently from directional precision. **Fail-closed/no-data is a valid research outcome, not an economic success.**

## Exactly three fixed policies for EACH fixed model

**P0 — STATIC-BASELINE:** no historical-day completeness gate. If current five-level book + strictly past five-quote history are invalid, return `DATA_UNAVAILABLE_CURRENT` (do not score); otherwise compare frozen D012 per-stock static cutoff (98th percentile of original April label-blind calibration score) with strict `score > cutoff`, producing `ALERT_UP`, `ALERT_DOWN`, or `NO_SIGNAL`. This baseline explicitly abstains on invalid current inputs and is not an endorsement for trading.

**P1 — STATIC+HISTORY-HEALTH:** exact same static cutoff as P0, but require ten immediately preceding COMPLETE observed common trading days (not ten selected good days) to each have **at least 50%** current-and-past-five valid, complete-book scores among all source snapshots that day, for that same stock. Threshold is a transparent prospective *engineering hypothesis* motivated by prior D014 sparse coverage—not tuned to unknown D015 outcomes. If any prior day falls below 50%, return `DATA_UNAVAILABLE_HISTORY` even when current row is valid. Current-row invalidity takes precedence over history. Do not use end-of-current-day information to determine today's eligibility. Each day's source/day quality may enter the gate only **after that day closes**.

**P2 — ROLLING+HISTORY-HEALTH:** identical current/history decisions as P1; for history-qualified stock/days only, fix each day's directional cutoff before that trading day to the `higher` 98th percentile across **all scores from the same previous ten complete observed common trading days**; strictly greater than cutoff to alert. Each of ten past days must satisfy the P1 50% source-eligibility minimum and contribute valid scores. Never use current-day scores, future targets, outcomes, or full-current-day aggregates for today's cutoff. On source/health failure, abstain with distinct reasons; no fallback or threshold substitution.

**No posthoc operating changes:** fixed 2% score budget, 10 previous observed common days, 50% previous-day quality, three policies/two models/three stocks, and no outlier/day selection. **No-data status is not a stationary forecast**, and no-signal is not a target prediction. For a stock-day with zero valid inputs or bad history, report 0 alerts and the *full unchanged source opportunity denominator*, not a conveniently restricted subset.

## Frozen outcomes and decision rule

- **Primary feasibility estimand:** partition **all confirmation source observations** by P0/P1/P2 status: `DATA_UNAVAILABLE_CURRENT`, `DATA_UNAVAILABLE_HISTORY`, `NO_SIGNAL`, `ALERT_UP`, `ALERT_DOWN`. Source-valid/current history coverage and prior-day health-by-stock/day, zero-score days, and 50%-gate coverage. All partitions sum exactly to total source observations. Missing data cannot be counted as false alarms or proof a model avoided an otherwise wrong alert.
- **Operating stability:** per model/policy/stock/day, counts and alert rate using **ALL source observations** and separately **decision-capable origins**; absolute deviation from 2% with both denominators clearly identified, plus fraction of stock-days >4% of all source rows, and maximum daily alert rate.
- **Scientific performance:** only future-label-verifiable confirmation observations, fully aligned same origin IDs for every policy; counts correct vs wrong directional alerts (wrong includes stationary and opposite sign), false alerts/1000 label-verifiable source origins, directional precision, up/down recall, 3-class true supports, abstentions by reason, optional 3-class proxy only clearly labelled. Also report descriptive fraction of target-observable directional movements occurring under DATA_UNAVAILABLE statuses (opportunity blind spot), never equate unobservable target with stationary.
- **Cost thought experiment:** +1 unit correct, −4 incorrect, 0 all other statuses; sensitivity ±1/−1 and +1/−9 only as alternate *hypothetical* costs, no measured trading P&L. 80% break-even precision on the primary 4:1 assumption if any alert is made. Zero-alert policy has utility exactly 0 and is an essential reference. Failure to issue signals is not considered a successful predictor.
- Day-clustered descriptive uncertainty: 2000 bootstrap iterations, seed 7007, resample ten **common dates with all three stocks together**, not tens of thousands of correlated quote origins as IID. No causal inference from five/ten days.
- **Stop/gate:** no model automatically promoted on this one confirmation. A trust claim requires nontrivial per-direction recall, consistently high enough precision for defined costs, stable alerting and availability across dates/stocks, and independent downstream evidence. Fail or document any source/hash/chronology/model reproducibility discrepancy without changing the split, stock list, gate or thresholds. Preserve the new D015 sealed final and all older final blocks unscored; keep Project 007 PR #7 draft/unmerged.
