# Engineering and analytical decisions

1. Existing repository is Python/Streamlit with project-local requirements and GitHub Actions. No Bottleneck implementation existed at inspection; no AGENTS.md was found. Isolate all work in this folder and a new workflow; preserve Optiver.
2. DataSF is the intended low-cost public path because no GCP identity or billing project is configured. Both metadata endpoints remain blocked in Codex, but GitHub-hosted Actions verified DataSF metadata and a small query with HTTP 200. Never infer schema or 2025 coverage from prior Baltimore work. Initial checked-in state is evidence pending.
3. The full live schema is recorded in `data/source_schema.json`; `agency_responsible` corrects the original agency mismatch. Extraction checks identity/types, uses numeric-ID keyset pagination, validates IDs across pages in transient SQLite, and reconciles before/after source counts and update metadata. Every raw page is normalized, checked and compared against SQL before aggregate shards are combined. The public API is mutable: these checks reduce but do not eliminate snapshot uncertainty. No paid service is enabled.
4. Retain all eligible unresolved requests. Inconsistent closure evidence is not a successful closure. Missing/unparseable creation timestamps and identity failures block publication. Ambiguous fall-back-hour times retain cohort membership and denominators, but exclude the affected request from successful closure counts and duration quantiles.
5. Use within-month/category leave-one-agency-out comparisons. No valid peer overlap means no adjusted result. A ≥30 eligible per-side cell threshold reduces unstable screens; this is a preliminary choice, not a power analysis. Persistence uses the user's ≥3 months/≥90 requests and 10/15-point rules.
6. Store additive day-grain aggregates; raw records stay in process memory and are never committed. Duration histograms support flexible filtering and reproducible approximate quantiles with <1 day error. Pin dependencies; no visitor credentials or API requests.
7. Geography uses a neighborhood heatmap and coverage table. Live metadata includes coordinates, but this acquisition intentionally omits them and has not verified coordinate coverage or boundaries. Keep the existing neighborhood heatmap. Reporting intensity is not a location-repeat failure measure.
8. Generated briefs label explanations as hypotheses. Recommendations are validation steps: verify work orders/outcomes, routing rules, status practices and subcategory complexity. Staffing and dispatch claims require separate evidence.
9. Synthetic records live only in test fixtures and temporary test directories; no demo data switch exists in production. A hash/provenance gate fails closed. This gate checks integrity, not authenticity against malicious falsification of metadata.
10. Acquisition artifacts remain unreviewed until explicit approval for promotion to `data/`. Actions has repository read permissions only and uploads no raw pages, IDs, shards or secrets. HTTP 428 encountered after 50,000 rows in the first full attempt led to two-second page pacing and bounded 428/429/server-error retries. No partial extract is presented as verified.
11. Deployment is prepared, not performed. No merge or main-branch write is performed. PR review and Community Cloud publication remain user-controlled.
